
**Принципы архитектуры:**

| Правило | Смысл |
|---|---|
| main.py тонкий | диспетчер: связь + роутинг задач + watchdog. Ноль бизнес-логики |
| Сервисы ≠ клиент ≠ сервер | фарм не знает про сервер, сервер не знает про фарм |
| Один файл — один писатель | `farm_state.json` пишет фарм, клиент только читает |

| Фарм = чёрный ящик | `services/farm/` не знает про сервер, сервер не знает про фарм; связь только через `info/`: `farm_state.json` (состояние) + `farm_events.jsonl` (события, этап 2) |
| Любого можно убить | систему поднимет один из слоёв неубиваемости |
| `client/` на сервере = истина | что там лежит — то и раздаётся телефонам при ⬆ |

**События фарма (этап 2):** фарм пишет в `info/farm_events.jsonl` (одна JSON-строка — одно
событие: `farm.start`, `bypass.start/ok/fail`, `farm.cycle`, `farm.restart`, `farm.stop/crash`).
Клиент (`core/events.py`, outbox) читает файл по offset'у, шлёт батч ≤50 по WS (`events`),
offset двигает ТОЛЬКО после `events_ack` — при потере связи батч уйдёт повторно, дубликаты
отсекает сервер (id = PRIMARY KEY). Сервер складывает в `farm.db` (SQLite).
Ротация файла: >512 КБ → хвост 300 событий. Планы дальше — `docs/будущий-функционал.md`.

**APK-менеджер (⬇ APK):** список ссылок лежит в github `staffere228-alt/apk` → файл `link-apps`
(одна ссылка на строку; можно `имя|ссылка` и #комментарии). Кнопка качает каждый APK,
ставит через `pm install -r -d` (su), сравнивает versionCode всех пакетов до/после.
Если хоть один APK реально обновил версию → телефон сам перезагружается (после отправки результата).

## 4. НЕУБИВАЕМОСТЬ (v5) — как реально работает

### Слои

```
Слой 6: keeper.sh (root-страж) — запускается при загрузке init.rc или service.d
        Лог: /data/local/tmp/farm-keeper.log. FBE-ожидание, фоллбеки
Слой 5: Termux:Boot → ~/.termux/boot/farm.sh
Слой 4: хук ~/.bashrc
Слой 3: supervisor.sh — python в foreground, умер → рестарт через 60с
Слой 2: main.py — WS-реконнекты
Слой 1: watchdog в main.py — сервисы, каждые 10с
+ selfheal в main.py — маркер≠v5 или supervisor мёртв → сам прогоняет setup.py
+ STOP-файлы: ~/farm/info/STOP + /data/local/tmp/.farm_stop
```

### ДИАГНОЗ ЭТОГО ТЕЛЕФОНА (важно! запомнить)

| Проверка | Результат | Следствие |
|---|---|---|
| root | ✅ «голый» su в прошивке | su работает, но… |
| Magisk/KernelSU/APatch | ❌ нет (`/data/adb/` пустая) | service.d не исполняется никем |
| SELinux | Disabled | seclabel не нужен (и не проверить) |
| `/system` | ❌ RO, dm-verity | init.rc установить НЕЛЬЗЯ |

**→ Единственный автозапуск после ребута: Termux:Boot.** setup.py сам скачивает и ставит APK через `pm install` (нужен лишь один раз открыть приложение руками).

**Что setup.py v5 пробует по порядку** (на новых телефонах сам выберет рабочее): init.rc в /system (если RW) → service.d (если есть менеджер) → Termux:Boot (всегда) → bashrc (всегда).

### Поведение по сценариям

| Сценарий | Кто спасает |
|---|---|
| Клиент упал | supervisor (слой 3), ≤60с |
| Сервис (farm/demo) упал | watchdog (слой 1), ≤10с |
| Termux убит системой (до ребута) | keeper: pidof → am start → bashrc |
| **Ребут телефона** | Termux:Boot → farm.sh → supervisor → клиент → сервисы по desired |
| Ребут → потом force-stop Termux | ⚠️ keeper после ребута НЕ поднят — см. «Ограничения» |
| Сломанный апдейт (клиент умирает мгновенно) | supervisor: рестарты с паузой 60с (клиент.log ротация), не зациклит |

### Ключевые механизмы

- **Живость клиента** = pid в `info/client.pid` + проверка cmdline «farm/main.py» (не скан по имени — иначе ловил бы `services/farm/main.py`)
- **desired state**: `service.start farm` → desired=running → после ребута main сам поднимет фарм
- **failing**: 5 рестартов сервиса за 3 мин → перезапуски стоп, ждёт ручного `service.start`
- **ENV/PATH**: клиент и сервисы стартуют с явным PATH Termux (`TERMUX_BIN`) — survives подъём от root-стража
- **selfheal**: при старте клиента проверяет `setup_done.json` (v:5) и supervisor → если что-то не так, сам переустанавливает неубиваемость
- **фарм-сервис**: сам находит su (PATH побит → /system/bin/su), ловит SIGTERM (сохраняет state и закрывает ВСЕ роблоксы — телефон остаётся чистым), не требует pip

## 6. ПРОТОКОЛ

**Телефон → сервер:** `hello` (device_id, версия, инфо) · `heartbeat` (каждые 30с: батарея, uptime, farm = farm_state.json для колонки 🔑) · `events` (батч событий фарма, этап 2) · `result` (ответ на задачу) · WS-ping.

**Сервер → телефон:** `welcome` · `heartbeat_ack` · `events_ack {accepted}` — после него клиент двигает offset (outbox) · `task`.

**События фарма (этап 2):** `farm.start` · `bypass.start` · `bypass.ok` (ключ+попытка) · `bypass.fail` · `farm.cycle` (сколько пакетов) · `farm.restart` (окно не было видно) · `farm.stop` · `farm.crash`.
Смотреть: кнопка 📅 на устройстве или `/api/events?device_id=...`.

**Задачи (сервер → телефон), v0.5:**

| task | payload | Результат |
|---|---|---|
| `ping` | — | pong, uptime |
| `exec` | `{command, timeout≤180}` | output (последние 4000 симв), код |
| `service.start/stop` | `{name}` | ok, pid |
| `service.status` | — | running/pid/desired/failing по каждому |
| `file.read` | `{path, tail≤20000}` | хвост файла, только внутри ~/farm |
| `update` | — | список обновлённого → самоперезапуск |
| `apk.update` | `{links_url?, reboot?}` | ставит APK из link-apps (github staffere228-alt/apk); `reboot:true` — перезагрузить всегда, `reboot:false` — никогда, без ключа — при реальном обновлении версии; ответ уходит ДО перезагрузки |
| `restart` | — | ответ → смерть → supervisor поднимет |
| `halt` | — | ответ → farm_stop.sh → полная остановка (роблоксы тоже закрыты) |

Задачи выполняются **в фоне** (`spawn`) — долгий exec не вешает связь. `update` валидирует: sha256 каждого файла + `compile()` для .py **до** применения; что-то не так → ничего не применено, ошибка уходит на сервер.

## 7. ОБНОВЛЕНИЕ ПО ВОЗДУХУ — рабочий цикл

```
1. Правишь ~/farm-server/client/... (в main.py подними VERSION!)
2. py_compile → curl /client/manifest (13 файлов?)
3. Дашборд → ⬆ / «Обновить всех»
4. Телефон: манифест → скачал изменившееся → проверил → применил атомарно
   → ответил → os._exit(0) → supervisor поднял нового → ● мигнул и вернулся
```

Откат = вернуть старый файл в `client/` → снова ⬆. Кривой файл не применится никогда (проверка до записи).

**Ручное** (если клиент совсем мёртв): `cd ~ && python boot.py` — докачает по sha256, убьёт старый клиент, поднимет supervisor. config.json никогда не трогается.

## 11. ТРОБЛШУТИНГ

| Симптом | Причина | Лечение |
|---|---|---|
| «unknown task» | клиент старый | дашборд ⬆, сверить колонку Версия = 0.5 |
| Телефон ● красный, exec не работает | клиент мёртв | sup/лог недоступны → на телефон: `tail supervisor.log`, `su -c tail .../farm-keeper.log` |
| После ребута не поднялся | Termux:Boot не открыт / PIN | открыть приложение 1 раз; снять блокировку |
| После ребута Termux убили — мёртв | keeper не живёт после ребута на этом телефоне | exec невозможен → открыть Termux руками, или заранее `su -c "setsid sh ~/farm/keeper.sh"` |
| update вернул syntax/hash error | битый файл на сервере | в ответе ⬆ есть причина → чинить client/ |
| Сервис failing | код падает | `лог` сервиса → чинить → `service.start` |
| Два ● драться (мигает) | клиент запущен руками + supervisor | `pkill -f farm/main.py`, отдать supervisor'у |
| supervisor.log молчит после ребута | Termux:Boot не отработал | открыть Termux:Boot, проверить `~/.termux/boot/farm.sh` |
| Все офлайн разом | сервер/туннель | `curl /health` локально, portmap Active, `systemctl status openvpn-portmap farm-api` |

## 12. ИЗВЕСТНЫЕ ОГРАНИЧЕНИЯ (честно)

1. **Keeper не переживает ребут на этом телефоне** (нет init.rc/service.d). После ребута охрану несёт только Termux:Boot+supervisor+bashrc. Фикс-команда: `su -c "setsid sh ~/farm/keeper.sh"`. В роадмапе: selfheal должен оживлять keeper'а при каждом старте клиента.
2. **API без авторизации** — любой, кто знает адрес portmap, рулит фермой. Закрыть на этапе безопасности.
3. **Ротация только у client.log** — supervisor.log и logs/services/* растут вечно.
4. PIN-телефоны: фарм после ребута стартует после первой разблокировки.
5. Termux:Boot APK качается с GitHub — при блокировке ставить руками из F-Droid.
